# 파킨온 수익화(구독+광고) 실행 계획

작성: 2026-07-04. 배경·근거는 [overseas_expansion_review.md](./overseas_expansion_review.md), [overseas_execution_plan.md](./overseas_execution_plan.md) Phase 5~7 참조.

## Context

해외(영어권) 출시를 위한 Phase 1(타임존)·Phase 4(법률/동의)까지 완료된 상태. 남은 건 오너가 확정한 **"C안"(다운로드 무료 + 구독 + 광고)** 수익화뿐이다. 구독의 심사 명분은 "광고 제거"가 아니라 **"클라우드 저장 확장"(SaaS)**이어야 Apple 자동갱신 구독 심사를 통과한다(광고 제거만으로는 거부됨). 구독·광고 SDK 모두 네이티브 모듈이라 **재빌드 1회가 반드시 필요**하며, 그 시점에 그동안 미뤄둔 앱 이름(파킨온→영문명, iOS/Android 표시명) 교체도 함께 반영한다.

코드베이스 탐색 결과 이 영역은 **완전히 그린필드**다 — IAP/구독/광고 관련 코드가 전혀 없고, 미디어 보관기간(`media_logs.expires_at`, 업로드 시 +6개월로 고정 세팅)도 **실제로 삭제를 실행하는 코드가 어디에도 없다**(주석에 "R2 lifecycle rule"이라 적혀 있지만 리포에서 확인 불가 — 사실상 방치된 상태). 이건 "구독=저장 용량/기간" 명분을 구현하려면 어차피 새로 만들어야 하는 부분이라, 수익화 작업과 자연스럽게 묶어서 처리한다.

**광고 배치 원칙 관련(2026-07-04 정정)**: 이전에 "핵심 복약/기록 화면 제외, 정보·커뮤니티 탭에만"이라는 원칙이 기록돼 있었으나, 오너가 "그런 결정 한 적 없다"고 정정 — **해외는 수익화 우선이며, 광고를 특정 화면에서 배제하지 않는다.** 다만 "마구잡이"는 안 된다는 지시에 따라 아래 절제된 배치안(배너 전용, 화면당 1개, 핵심 조작 버튼과 분리된 고정 위치)을 적용한다.

## Phase 5 — 수익화 백엔드 설계 (OTA 가능, 재빌드 불필요)

### 5.1 DB 스키마 (2026-07-07 확정: **그룹 단위 구독**)
구독은 개인이 아니라 **가족 그룹(patient_group) 단위**다. 근거: 미디어가 `media_logs.patient_id`(환자 중심)라 저장이 애초에 환자/그룹 공유이고, `users.patient_group_id`로 유저는 항상 1개 그룹에 속함(1인 1그룹). 그룹 구성원 아무나 1명이 결제하면 그룹 전체가 Premium.
- `patient_groups`에 컬럼 추가: `subscription_tier text NOT NULL DEFAULT 'free'` (`'free' | 'premium'`), `subscription_expires_at timestamptz`, `subscription_payer_user_id uuid`(결제자 기록), `revenuecat_synced_at timestamptz`(선택).
- 어떤 유저의 실질 티어 = `users.patient_group_id` → 해당 그룹의 `subscription_tier`. (그룹 없으면 free fallback, 정상 온보딩 시 항상 그룹 존재)
- RevenueCat `appUserID`는 Supabase `users.id`(결제자). webhook에서 결제자의 `patient_group_id`를 찾아 **그 그룹**을 premium으로 승격 + `subscription_payer_user_id` 기록.
- 페이월 노출 전 그룹이 이미 premium이면 "이미 프리미엄" 처리(중복 결제 방지).

### 5.2 저장 티어 정의 (2026-07-07 오너 **최종 확정**: 총량 제한 없음 · **그룹당 하루 업로드 풀**)
R2 요금 분석(egress **무료** + 저장 $0.015/GB·월 + 첫 10GB 무료 + 영상 2분 상한으로 파일크기 이미 묶임)상 총 저장량 제한 불필요. Free가 매일 상한을 꽉 채워도 그룹당 1년 누적 ~수 GB = 월 몇 센트. 그래서 "총량"이 아니라 **"그룹당 하루 업로드 개수"**로 게이팅한다.

**미디어 업로드 지점(해외)은 2곳뿐**: ① **일기**(사진/영상/**음성** 지원, `diaryMedia.ts` photo/video/audio 토큰. 작성기 기존 캡 = 사진 5·영상 1≤2분·음성 1, `diary.attachHint`. 저장: diary 행의 `photo_urls[]`/`video_media_id`/`audio_url`). ② **몸상태 영상**(별도, `saveMediaLog`→`media_logs`, 현재 무제한). 사진은 일기에만(해외 커뮤니티 없음).

- **Free — 그룹당 하루 공유 풀**(구성원·작성자 무관, 선착순): **사진 5 · 영상 2(일기1 + 몸상태1) · 음성 1**. **광고 유지.**
  - 풀은 **그룹(환자) 단위**다. 그룹 내 누군가 그날 풀을 다 쓰면(사진5+영상2+음성1) 다른 구성원은 그날 미디어 첨부 불가 → 내일 등록 or 결제 유도(오너 의도: 자연스러운 전환 압력). *텍스트 일기 작성 자체는 각자 가능, 막히는 건 미디어 첨부만.*
  - 카운트 정의 = **"오늘 그 그룹에 현재 붙어있는 미디어 수"**(누적 업로드 이벤트 아님) → 삭제하면 슬롯 복구(사용자 친화적). 오늘치 diary 행들 + 오늘치 body_state `media_logs`를 타입별 합산.
- **Premium**(그룹 단위, 구성원 1명 결제로 그룹 전체 승격): **사진·영상·음성 무제한 + 광고 제거(그룹 전체=A안).** 일기 작성/수정 하단 `attachHint` 캡 문구 **숨김**. free에겐 그 자리를 **"프리미엄이면 무제한" 구독 유도 문구**로 교체.
- `subscription_tier`는 `'free' | 'premium'` 2값만.
- **다운그레이드 grandfathering**(오너 확정): 프리미엄 때 올린 기존 미디어는 **유지**(소급 삭제 없음), free 전환 후엔 그날 풀 초과분 **신규 첨부만 차단**.
- **다중 작성자 불허**(오너 확정): 풀이 그룹 공유이므로 자동 성립(위 참고).
- 총 개수·보관기간 상한 **없음** → 5.4의 `expire-media` 크론 불필요, `calcExpiresAt` 만료 로직 폐기(신규 업로드 `expires_at=null`, 자동삭제 안 함).
- ⚙️ 구현 노트: 일기 미디어(diary 행 컬럼)와 몸상태 영상(`media_logs`)이 **저장 위치가 달라**, 그룹 하루 카운터는 두 소스를 타입별로 합산해야 함(Phase 5에서 통합 카운트 헬퍼 필요). 하루경계=환자 timezone 기준(Phase 1 tz 재사용).

### 5.2b 구독 가격 (2026-07-07 외부 조사 기반 제안)
외부 조사 결과(2026-07 기준):
- **Medisafe**(가장 가까운 직접 경쟁 = 복약 관리 앱): 프리미엄 **$4.99/월 · $39.99/년** (2026-01부터 무료 2약 제한).
- 헬스&피트니스 앱 구독가 **글로벌 중앙값 $7.48/월**(Adapty 2026). 연간제가 지배적·리텐션 우월(저가 연간 최대 36% 잔존 vs 고가 월간 6.7%, RevenueCat).
- MyFitnessPal $19.99/월·$79.99/년(상위 포지션 참고선).

> ⚠️ **실제 출시된 상품과 다르다 (2026-08-12 확인).** 아래 "연 $39.99"는 계획 단계의 값이고,
> 실제로는 **월간 상품 하나 + 7일 무료체험**으로 출시됐다. 연간·평생 상품은 만들지 않기로 한
> 오너 결정이며, 코드에도 그렇게 적혀 있다(`SubscriptionManageScreen.tsx:307`
> "플랜 — 월간 하나뿐(오너 결정: 연간/평생 없음)"). 무료체험은 연간이 아니라 월간에 붙어 있다.
> 가격 자체는 스토어에서 받아 표시하므로 이 문서의 숫자를 근거로 삼지 말 것.

**계획 단계 가격(USD 기준가, 2026-07-07 오너 동의):** **월 $4.99 / 연 $39.99** (연간 = 실질 월 $3.33, 약 33% 할인) + **연간에 7일 무료체험**(Adapty: 헬스 카테고리에서 트라이얼이 LTV 유의미 상승).
- 근거: 카테고리 리더 Medisafe와 동일가로 붙어 가격 저항 최소화 + 헬스 중앙값($7.48) 아래라 60대+/보호자에게 접근성. 연간 강할인으로 리텐션 확보.
- 스토어 다국가 가격은 App Store/Play의 가격 티어가 USD 기준가에서 GBP/CAD/AUD/EUR/NZD로 자동 환산 → 오너는 USD 기준가만 결정하면 됨.
- 가격은 스토어 콘솔 설정값이라 나중에 A/B·변경 용이(RevenueCat로 손쉬움).

### 5.3 업로드 시 게이팅 (그룹당 하루 풀 기반)
- 업로드/첨부 직전 quota 체크(premium이면 전부 통과). free면 **그룹(환자)의 오늘(환자 tz 하루경계) 현재 미디어 수**를 타입별로 세어 한도(사진5·영상2·음성1)와 비교, 차 있으면 차단 + "오늘 한도를 다 썼어요 → 프리미엄으로 무제한" 업그레이드 유도(`useDialog`, 진입점=6.1 SubscriptionManageScreen).
- 통합 카운트: `오늘 diary 행들의 photo_urls 합계`(사진) + `오늘 diary 행 중 video_media_id 존재 수` + `오늘 body_state media_logs video 수`(영상 = 이 둘 합) + `오늘 diary 행 중 audio_url 존재 수`(음성). "현재 붙어있는 수" 기준이라 삭제 시 슬롯 복구.
- 하루경계는 환자 timezone 기준(Phase 1 tz 인프라 재사용, `now() at time zone u.timezone`).
- 일기 작성기: 기존 하드캡(5/1/1)을 **free일 때만 그룹 하루 잔여로 재계산**, premium이면 캡 해제. 몸상태 영상: free=그룹 하루 잔여(영상 풀 공유), premium=무제한.
- `calcExpiresAt()`(r2Upload.ts, 현재 +6개월 고정)은 **만료 폐기** → 신규 업로드 `expires_at=null`(자동삭제 안 함). 컬럼 자체는 하위호환 위해 유지하되 미사용.

### 5.4 (폐기) 만료 삭제 크론 불필요
새 모델은 총량/보관기간 상한이 없어 원래 계획한 `expire-media` 자동삭제 크론이 **불필요**. 구현하지 않는다. (취소해도 기존 미디어 유지 = 자동으로 성립. 신규 업로드만 free 하루 한도로 게이팅됨 = "유예기간 읽기전용" 대체)

### 5.5 광고 배치 설계 — 화면·위치 확정(2026-07-07 오너 결정, 광고 포맷=네이티브로 정정)

**광고 포맷은 배너가 아니라 네이티브 광고로 확정.** 이전 초안(배너 전용)은 "60대+ 오조작 방지" 논리로 세운 것이었는데, 오너가 명확히 정정함: 해외판은 수익화가 최우선이고, 네이티브 광고가 디자인적으로도(앱 톤앤매너에 맞춰 자체 제작 가능) 수익적으로도(eCPM이 배너보다 높음) 우월하다고 판단 — 이 논쟁 재소환 금지.

노출 화면은 메인 탭 랜딩 5곳 + 기록 보기로 한정(그 외 상세/작성/설정/온보딩/다이어리는 광고 제외 — "너무 적지도, 불편할 정도로 많지도 않게"가 기준). 각 화면 내 정확한 삽입 위치:

- **약복용 / 몸상태 / 운동 탭**: 오늘 기록 리스트의 **첫 번째 슬롯 자리에 네이티브 광고를 끼워 넣는다**(슬롯 목록 최상단 = 광고, 그 아래부터 실제 오늘 슬롯들).
- **Reminders 탭 → "약 관리" 서브탭**: **처방전 등록 버튼 바로 아래**에 네이티브 광고 1개.
- **Reminders 탭 → "복용 시간·알림 설정" 서브탭**: **첫 번째 슬롯 카드와 두 번째 슬롯 카드 사이**에 네이티브 광고 1개(위 2개 화면과 다르게 맨 위가 아니라 1·2번 사이).
- **More 메뉴**: **첫 번째 섹션(기록 sectionRecords)과 두 번째 섹션(관리 sectionManage) 사이**에 네이티브 광고 1개.
- **웹으로 보기(parkinon-web)**: 토큰 교환 스피너가 끝나고 Records 화면이 뜬 뒤 **몇 초 지나서 화면 하단에서 올라오는 큰 배너**(웹은 AdSense 등 별도 스택이라 네이티브 렌더링 난이도가 앱과 다름 — 웹만 배너 유지, 필요시 재검토).

공통 원칙:
- 네이티브 광고(제목+이미지+CTA를 앱 카드/리스트 스타일로 자체 템플릿 제작), 화면당 정확히 1개. 전면(인터스티셜) 광고는 이번 범위 밖.
- "Ad" 표시는 정책상 필수 유지(완전히 숨기면 정책 위반) — 다만 크기·톤은 눈에 띄지 않게 최소화.
- 비개인화(`npa=1`) 고정, 건강데이터 광고 SDK 미전달(기존 방침 유지).
- 온보딩·동의 화면·다이어리(정서적 화면)는 광고 제외.

**배치 자체는 순수 JS 조건부 렌더링이라 OTA로 자유롭게 추가·제거·위치변경 가능**(6.2의 최초 SDK 네이티브 통합 1회만 재빌드 필요 — 아래 6.2 참고).

## Phase 6 — 수익화 통합 (⚠️ 네이티브 재빌드 1회 필요)

### 6.1 IAP 구독 — RevenueCat 채택
- 이유: 영수증 검증·구독 상태 서버 동기화를 자체 구현하지 않아도 됨(webhook 하나로 해결), `react-native-purchases` SDK 성숙도 높음, 무료 티어(MTR $2.5k 이하)로 이 단계 비용 0.
- `revenuecat-webhook` Edge Function 신규: RevenueCat이 구매/갱신/취소/만료 이벤트를 보내면 `users.subscription_tier`/`subscription_expires_at` 갱신(기존 `kakao-auth` 류 webhook 패턴과 동일 구조).
- 클라: `src/hooks/useSubscription.ts` 신규(user.subscription_tier 기반 `isPremium` 노출) + `SubscriptionManageScreen.tsx` 신규(`MenuNavigator`에 라우트 추가).
- 페이월 UI는 RevenueCat 기본 템플릿 대신 **자체 제작**(이 앱의 큰 버튼·18sp+ 텍스트·고대비 디자인 시스템 일관성 유지 목적).

**구독 화면 진입점 확정(2026-07-07 오너 결정)** — 전부 동일한 `SubscriptionManageScreen` 하나로 연결:
1. **More 메뉴 최상단** — 기존 sectionRecords보다 위에 새 섹션 추가("Free Plan" 배지 + "Upgrade" 버튼 한 줄, 프로필 카드 바로 아래).

### 6.2 광고 SDK — `react-native-google-mobile-ads`(AdMob)
- **앱: 네이티브 광고**(위 5.5 설계, `NativeAd`/`NativeAdView` API) — 자체 카드/리스트 스타일 템플릿 제작. 전면(인터스티셜) 광고는 이번 범위 밖.
- **웹(parkinon-web)**: 배너 유지(위 5.5 참고, 스택이 달라 네이티브 난이도 높음).
- iOS: ATT 프롬프트 + `NSUserTrackingUsageDescription`(app.json에 없음, 신규 추가) + `SKAdNetworkItems` + `GADApplicationIdentifier`.
- Android: `AD_ID` 권한 재도입(GMA SDK가 자동 병합하나 명시 확인) + Play 콘솔 광고ID 선언.
- `app.json`의 `expo.plugins`(현재 9개, ads/iap 플러그인 없음)에 `react-native-google-mobile-ads`, `react-native-purchases`(플러그인 필요시) 추가.

**OTA 경계선(2026-07-07 질의응답 정리)**: 네이티브 모듈(SDK) 자체를 앱 바이너리에 넣는 최초 통합은 이 6.2 재빌드 1회에서만 가능 — 이후엔 별도 재빌드 없이 다음이 전부 OTA(순수 JS)로 가능함:
- 네이티브 광고 노출 화면 추가/제거, 화면 내 위치 변경(5.5의 배치는 전부 조건부 렌더링일 뿐).
- 광고 개수·노출 빈도 조정, 지연 노출 타이밍 변경, 템플릿 디자인 수정.
- 광고 unit ID 교체, 비활성화(플래그로 전체 off).
재빌드가 다시 필요해지는 경우: 전면(인터스티셜) 등 이번에 통합 안 한 새 광고 "포맷" 도입, 또는 SDK 자체 메이저 업데이트로 네이티브 설정이 바뀌는 경우 정도.
