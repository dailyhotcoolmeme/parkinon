# 번역 규칙 — 빠뜨리지 않기 위한 것

2026-07-29 프랑스어·일본어를 넣다가 실패하고 오너와 정리한 규칙.
새 언어를 넣을 때는 **이 문서 순서대로** 한다. 순서를 바꾸거나 건너뛰지 않는다.

---

## 0. 왜 실패했나 (같은 실수를 안 하려고 남긴다)

번역 파일 1,884개를 100% 채우고 "누락 없음"이라고 보고했다. 그런데 실기기에서
프랑스어로 열자마자 **한글 `아침`** 이 나왔고, 다른 화면은 **영어 `Morning 9:00`** 이
나왔다.

원인은 하나가 아니라 셋이었다.

| 한글이 화면에 나가는 경로 | 내가 한 것 | 결과 |
|---|---|---|
| ① 코드에 박힌 화면 문구 | 번역 파일에 fr/ja 채움 | 정상 |
| ② 코드에 박힌 한↔영 변환표 | **손도 안 댐** | fr/ja 인데 영어가 나옴 |
| ③ DB에 저장된 한글 값 | **손도 안 댐** | 변환을 빠뜨린 화면에서 한글이 나옴 |

②③을 "번역 대상"으로 인식조차 못 했다. 번역 = 번역 파일이라고만 생각했다.

그리고 더 나쁜 것: **한글 1,139건을 기계로 다 찾아놓고, 내가 손으로 1,138건을 걸렀다.**
`label: '아침'` 을 보고 "이건 내부 식별자겠지"라고 **추측**해서 뺐다. 실제로는 그 값이
그대로 DB 에 저장되는 값이었다. 확인하지 않은 추측을 오너에게는 "확인했다"고 말했다.

---

## 1. 한글은 네 군데에 있다 — 네 군데를 다 훑는다

찾는 건 어렵지 않다. 한글은 유니코드 구간이 정해져 있어 `[가-힣]` 하나로 빠짐없이 나온다.
**어려운 건 찾는 게 아니라, 찾은 걸 안 거르는 것이다.**

| 대상 | 훑는 법 |
|---|---|
| 앱 코드 | `src/**/*.{ts,tsx}` 전체에서 `[가-힣]` |
| 웹 | `parkinon-web/` 전체에서 `[가-힣]` |
| 서버 | `supabase/functions/**` 전체에서 `[가-힣]` |
| **DB** | 모든 테이블의 문자 컬럼에 `~ '[가-힣]'` |

DB 를 빠뜨리지 말 것. `아침` 사고가 여기서 나왔다.

## 2. 절대 규칙

### R1. 기본값은 "전부 번역한다". 빼는 것은 오너 승인 없이는 불가능하다
찾은 한글은 **전부 번역 대상**이다. 이게 기본값이고, 예외는 없다.

"이건 내부 식별자다", "이건 화면에 안 나간다" 같은 판단은 **내가 내리지 않는다.**
근거를 남기는 것으로는 부족하다 — 근거는 내가 쓰는 것이라, 잘못 생각하고 그럴듯하게
써버리면 그대로 빠져나간다. 실제로 이번에 `label: '아침'` 을 "내부 식별자"라고 적고 뺐다.

그러므로:

1. 나는 **"제외 후보 목록"만** 만든다. 스스로 빼지 않는다.
2. 각 후보에 `파일:줄` 로 지목한 자료를 붙여 오너에게 제출한다.
   (그 자료는 통과 사유가 아니라, 오너가 판단할 재료다.)
3. **오너가 승인한 것만 제외된다.** 승인 전까지는 전부 번역 대상으로 남는다.
4. 애매하면 뺄 생각을 하지 말고 **그냥 번역한다.** 번역해서 손해 보는 경우는 없다.

### R2. 번역 파일 완성도를 "누락 없음"이라고 말하지 않는다
`i18n-check` 통과는 **"파일에 값이 채워져 있다"** 는 뜻이다.
**"화면에 그 값이 나온다"** 는 뜻이 아니다. 이 둘은 다른 문제다.

### R3. 한↔영 변환표를 전부 찾아 언어별로 만든다
코드에는 번역 파일과 별개로, 한국어를 영어로 바꾸는 표가 흩어져 있다.

```ts
const LEGACY_LABEL_EN = { morning: 'Morning', lunch: 'Lunch', ... };   // ← 이런 것
if (isOverseasLocale()) return 'Early morning';                        // ← 이런 것
```

**영어만 있는 자리는 새 언어에서 영어가 나온다 = 미완성이다.**
찾는 법: `isOverseasLocale()` / `isKoLocale()` 분기를 전부 뽑는다. 그 분기의 "해외" 쪽에
i18n 키가 아니라 영어 문자열이 박혀 있으면 전부 대상이다.
→ 발견하면 그 자리를 **언어 파일 키로 옮긴다.** 영어를 하나 더 늘리지 말 것.

### R4. DB 에 저장되는 한글은 목록으로 관리하고, 단일 함수로만 그린다
DB 값은 번역 파일에 넣을 수 없다(사용자마다 다르고 가입 시 코드가 써넣는다).

지금 확인된 것:
- `dose_slots.label` = `'아침' / '점심' / '저녁' / '취침'`
- 약효추적 시점 라벨 = `'복용 직후' / '30분 후' / …`

규칙:
1. 새 언어를 넣을 때 이 목록의 **모든 값**에 그 언어를 추가한다.
2. 이 값을 화면에 그리는 **모든 지점**은 반드시 공용 변환 함수를 거친다
   (`translateRawSlotLabel()` 등). 화면마다 자기 함수를 만들지 않는다.
   → `아침` 사고는 운동 화면이 공용 함수를 안 쓰고 자기 함수를 만들어서 났다.
3. 새 화면에서 DB 라벨을 그릴 때, 공용 함수를 안 거치면 리뷰에서 막는다.

### R5. 번역 원문은 `ko.json` 이다
영어판을 보고 옮기면 영어판의 오역·누락을 그대로 물려받는다.
영어를 참고하는 건 좋지만, **최종 대조는 한국어 원문으로 한다.**

### R6. 보고할 때 쓸 수 있는 말은 둘뿐이다
- "검사 통과" — **검사기 출력을 함께 붙일 때만**
- "미확인"

눈으로 보고 괜찮아 보인 것은 **미확인**이다. 축소된 스크린샷으로 판단하지 않는다.

## 3. 새 언어 추가 순서

### 1단계 — 전수 추출 (거르지 않는다)
앱·웹·서버·DB 네 군데에서 한글을 전부 뽑는다. **먼저 총 건수를 오너에게 보고한다.**
거른 뒤의 숫자가 아니라 **거르기 전 숫자**를 보고한다.

### 2단계 — 분류 (근거를 남긴다)
각 건을 셋 중 하나로 분류하고, 제외한 것은 R1 대로 근거를 적는다.
- ① 화면 문구 → 번역 파일로
- ② 한↔영 변환표 → 언어 파일 키로 옮기고 새 언어 추가
- ③ DB 저장값 → R4 목록에 넣고 새 언어 추가

### 3단계 — 번역
`ko.json` 을 원문으로 옮긴다. 네임스페이스 단위로 쪼개서
`scripts/i18n-merge.mjs` 로 합친다.

의학 용어·복약 문구는 직접 번역한다. 서브에이전트에 맡기지 않는다(오너 확정).

### 4단계 — 앱에 등록
1. `src/i18n/locales/<lang>.json`
2. `src/i18n/detectLocale.ts` → `SUPPORTED_LANGUAGES`
3. `src/i18n/index.ts` → `resources`
4. `src/i18n/detectLocale.ts` → `DISPLAY_TAGS` (날짜 포맷 로케일)

### 5단계 — 서버
`supabase/functions/_shared/i18n.ts` 의 `Lang` / `SUPPORTED` / `STRINGS` 에 추가.
배포 후 **반드시 실제 호출로 부팅 확인** (import 누락은 배포는 되고 런타임에만 터진다).

### 6단계 — 검증
- `node scripts/i18n-check.mjs <lang>` — 키 누락·한글 잔존·변수 불일치
- `node scripts/i18n-fit-check.mjs <lang>` — 좁은 자리 넘침
- **개발빌드**로 실기기에서 확인. Release 빌드로 하면 `hangulGuard` 가 꺼져 있어
  화면에 한글이 나와도 아무 경고가 없다. ← 이번에 이걸 틀렸다.

### 7단계 — 앱 밖
- iOS 권한 문구 `locales/<lang>.json` (네이티브 — OTA 불가, 다음 빌드부터)
- Play / App Store 등록정보, 구독 상품 등록정보
- 웹 약관·개인정보처리방침 페이지

## 4. 근본 대책 (다음 언어 전에 해두면 좋은 것)

`아침` 같은 사고를 구조적으로 없애려면 **DB 에 표시용 글자를 저장하지 않는다.**
`'아침'` 대신 `morning` 을 저장하면, 화면은 키를 받아 번역 파일에서 꺼내므로
①과 같은 경로가 된다. 변환을 빠뜨릴 화면 자체가 없어진다.

기존 데이터는 `'아침' → morning` 으로 한 번 마이그레이션하면 된다.

지금 방식(DB 에 한글 저장 + 화면에서 변환)으로도 동작은 한다. 다만 화면이 늘어날 때마다
변환을 빠뜨릴 위험이 계속 남는다.

## 5. 수행 규칙 — 이 순서를 어기면 이번 사고가 반복된다

### E1. 거르기 전 숫자를 먼저 보고한다
1단계에서 나온 **원본 건수**를 먼저 보고한다. "1,139건 나왔습니다"가 먼저고,
분류는 그다음이다. 줄인 숫자만 보고하면 오너가 무엇이 걸러졌는지 볼 수 없다.

### E2. 분류 결과를 감사 가능한 파일로 남긴다
`docs/i18n_audit_<lang>.md` 에 표로 남긴다.

| 파일:줄 | 한글 | 분류 | 근거 |
|---|---|---|---|
| constants/doseSlots.ts:49 | `'아침'` | ③ DB저장값 | useDoseSlots.ts:475 에서 `label: meta.label` 로 insert |
| SettingsScreen.tsx:1552 | `'오전'` | 제외 | 타입 유니온. 화면은 `t('common.am')` — DoseSlotSetList.tsx:1649 |

**제외 칸의 근거는 "파일:줄" 로 지목한다.** "~같음", "~일 것이다" 금지.

### E3. 단계마다 기계 출력을 붙인다
각 단계를 "끝났다"고 말할 때 그 단계의 명령 출력을 함께 낸다.
출력 없이 끝났다고 하지 않는다.

### E4. 언어는 하나씩 끝낸다
프랑스어를 6단계까지 통과시킨 뒤 일본어를 시작한다.
두 언어를 동시에 진행하면 검증이 섞여 무엇이 확인된 건지 알 수 없어진다.
(이번에 fr·ja 를 같이 만들고 같이 배포해서 둘 다 미검증 상태가 됐다.)

### E5. 검증 전에 배포하지 않는다 — 가장 중요
이번 사고의 실질적 피해는 "틀렸다"가 아니라 **"틀린 채로 이미 나갔다"** 이다.
OTA 3개 런타임, Play 등록정보, 일본 출시 심사까지 전부 검증 전에 밀어 넣었다.

순서를 고정한다.

```
번역 → 검증(6단계 전부 통과) → 오너 확인 → 배포
```

- 검증 미통과 상태로는 OTA·스토어 제출을 하지 않는다.
- 검증이 오래 걸리면 **언어를 `SUPPORTED_LANGUAGES` 에서 빼둔 채로** 코드만 병합한다.
  그러면 배포돼 있어도 사용자에게는 안 보인다.

## 6. 검증 규칙 — 3중으로 본다

한 겹으로는 못 잡는다. 이번에 1겹(번역 파일)만 보고 통과시켰다.

### V1. 정적 — 번역 파일
```
node scripts/i18n-check.mjs <lang>
```
키 누락 / 한글 잔존 / `{{변수}}` 불일치. **잡는 범위: ① 경로뿐.**

### V2. 정적 — 코드 경로
1단계 전수 추출 + 2단계 분류표(E2)가 이 역할을 한다.
`isOverseasLocale()` 분기 중 해외 쪽에 영어 문자열이 박힌 곳이 0건이어야 한다.
**잡는 범위: ②③ 경로.**

### V3. 런타임 — 실기기 (완료 근거가 아니다. 발견만 추가한다)

**V3 로는 "다 확인했다"고 말할 수 없다.** 내가 열 수 있는 화면만 검사되기 때문이다.
오류 팝업·빈 상태·보호자 모드·네트워크 실패는 내가 다 만들어낼 수 없다.
완전성은 V1+V2 가 담당하고, V3 는 **거기서 새어나온 것을 잡는 그물**이다.

그리고 V3 에서 **내 눈은 판정에 쓰지 않는다.** 좀 전처럼 "보기엔 괜찮다"로 넘어가는 걸
막기 위해, 판정은 전적으로 앱이 한다.

내가 하는 일 / 앱이 하는 일을 나눈다.

| 나 | 앱 |
|---|---|
| 개발빌드를 기기에 올린다 | 화면에 글자를 그릴 때마다 검사한다 |
| 화면을 연다 | 한글이 그려지면 로그를 찍는다 |
| 로그를 수집한다 | 글자가 상자를 넘치면 로그를 찍는다 |
| 로그 **원본 파일**을 오너에게 낸다 | 어느 화면인지 함께 기록한다 |

- 결과물은 **로그 파일**이다. 내 요약이 아니라 파일을 낸다.
- 로그가 비어 있어도 그건 "내가 연 화면에서 안 걸렸다"는 뜻이지 "전부 정상"이 아니다.
- 스크린샷은 참고 자료일 뿐 **판정 수단이 아니다.**
- 로그에 한 건이라도 있으면 **배포 불가**다.

### V4. 화면 커버리지를 목록으로 남긴다
V3 는 "내가 연 화면"만 검사한다. 그러므로 **연 화면 목록을 남긴다.**
안 연 화면은 "문제없음"이 아니라 **"미확인"** 이다.

오류 팝업·빈 상태·보호자 모드·네트워크 실패처럼 재현하기 어려운 화면은
V2(코드 경로 점검)로 덮는다. V3 만으로 완전하다고 말하지 않는다.

### V5. 스크린샷은 확대해서 본다
축소본으로 판단하지 않는다. 버튼·라벨 단위로 잘라 2배 이상 확대해 확인한다.
("Vidéos enregistrées" 가 버튼 밖으로 나간 걸 축소본에서 못 봤다.)

## 7. 버튼·상자 안 글자 규칙

60대 이상이 쓰는 앱이라 글씨 18sp+ / 버튼 56dp+ 가 고정이다.
**번역이 길다고 폰트를 줄이지 않는다.** 문구를 짧게 잡는다. (오너 확정)

### L1. 위험한 자리는 정해져 있다
"고정폭 + 한 줄" 조합이면 넘친다.

- `flex: 1` 로 2·3·5 등분된 버튼/탭/칩 ← **가장 위험**
- `numberOfLines={1}` 이 걸린 텍스트
- 좌우에 고정폭 상자가 있는 가운데 정렬 제목 (TopBar)
- 아이콘과 가로로 나란히 놓인 라벨

### L2. 가용 폭 계산법
```
가용 폭 = 컨테이너 폭 − 좌우 padding − 아이콘 폭 − gap − 테두리
```
예) 영상 버튼: (393 − 32 − 10) ÷ 2 = 175.5pt, − 아이콘 24 − gap 10 = **141pt**

### L3. 새 언어 문구는 넣기 전에 예산 안에 맞춘다
```
node scripts/i18n-fit-check.mjs <lang>
```
❌ 가 뜨면 **문구를 줄인다.** 폰트를 줄이거나 `adjustsFontSizeToFit` 을 새로 붙이지 않는다.

### L4. 검사 목록을 내가 손으로 고르지 않는다
`i18n-fit-check` 의 슬롯 목록은 내가 고른 것이라 **목록에 없으면 무방비다.**
(영상 버튼이 목록에 없어서 뚫렸다.)

그러므로 **런타임 실측이 본검사이고, fit-check 는 사전 경보일 뿐이다.**
새 화면·새 버튼을 만들면 슬롯을 추가한다. 추가를 잊어도 런타임 가드가 잡는다.

### L5. 런타임 실측 — 앱이 스스로 신고한다
`onTextLayout` 이 주는 **각 줄의 실제 렌더 폭** 과
`onLayout` 이 주는 **그 텍스트에 주어진 상자 폭** 을 비교한다.
줄 폭 > 상자 폭 이면 넘친 것이다. 추정표가 아니라 렌더링 결과다.

`hangulGuard` 와 같은 방식으로 `Text` 를 전역 패치해 개발빌드에서만 동작시킨다.
→ 화면을 열기만 하면 넘친 곳이 전부 로그로 나온다. 내가 목록을 고를 필요가 없다.

### L6. 말줄임(…)도 실패로 본다
`numberOfLines={1}` 때문에 잘려서 `…` 이 뜬 것은 "안 넘쳤다"가 아니라
**정보가 사라진 것**이다. 실패로 처리하고 문구를 줄인다.

### L7. 줄바꿈으로 상자가 커지는 것도 확인한다
알림창·카드처럼 높이가 늘어나는 곳은 안 잘리지만 레이아웃이 흉해진다.
2줄까지는 허용, 3줄 이상이면 문구를 줄인다.

# V6. 렌더 기반 검수 설비 (2026-07-30 신설)

파일 검사만으로는 DB·코드에서 나오는 한글을 못 잡는다("Next 아침" 사고).
그래서 **실제로 화면에 그려진 문자열**로 판정한다. 사람 눈이 아니라 앱이 판정한다.

## 구성

| 파일 | 역할 |
|---|---|
| `src/i18n/textHook.ts` | 모든 `<Text>` 렌더를 후킹하는 단 하나의 지점 |
| `src/i18n/hangulGuard.ts` | 해외 언어인데 한글이 그려지면 보고 |
| `src/i18n/layoutGuard.ts` | 줄 폭 > 상자 폭이면 보고(실측) |
| `src/i18n/qaProbe.ts` | 그려진 문구를 맥의 수집기로 전송 |
| `src/i18n/qaWalk.ts` | 화면 자동 순회(좌표 아닌 라우트 기반) |
| `scripts/qa-run.mjs` | 시뮬레이터 세팅·로그인·순회 시작 |
| `scripts/qa-collector.mjs` | 이벤트 수집 |
| `scripts/qa-report.mjs` | 한글노출·넘침·**키 커버리지** 계산 |

## 실행

```
node scripts/qa-collector.mjs fr &
QA_PASSWORD=... node scripts/qa-run.mjs fr
node scripts/qa-report.mjs fr
```

## 규칙

- **V6-1** 새 언어는 이 순회를 돌리고 리포트를 첨부하기 전에는 "검수했다"고 말하지 않는다.
- **V6-2** 한글 노출은 **0건**이어야 한다. 광고 SDK 문구처럼 우리 것이 아닌 항목을
  빼려면 R1 대로 **오너 승인**을 받는다(스스로 판단해 빼지 않는다).
- **V6-3** 리포트의 **미노출 키 목록이 곧 남은 숙제**다. "몇 화면 봤다"가 아니라
  "몇 개 키가 아직 안 떴다"로 보고한다. 순회는 화면 진입까지만 커버하므로
  나머지는 시나리오(버튼·팝업·에러)로 채운다.
- **V6-4** 개발 빌드는 배포된 OTA 번들을 받아 실행하므로, 검수 전 `EXUpdatesEnabled`
  를 꺼야 로컬 코드가 반영된다(`qa-run.mjs` 가 자동 처리). 이걸 모르면 고친 코드가
  아니라 이미 배포된 코드를 검수하게 된다.

## 알려진 함정 (다시 밟지 말 것)

- RN 0.81 부터 `Text.render` 가 없다 → `Text.render` 패치 방식 가드는 **조용히 무력**해진다.
  JSX 런타임(`jsxDEV`)을 후킹해야 한다. 2026-07-30 이전의 가드는 전부 헛돌고 있었다.
- AsyncStorage 는 `Documents` 가 아니라 `Library/Application Support/<bundleId>` 에 있고,
  1024자 초과 값의 파일명은 키의 MD5 **소문자** 16진수다.
- iOS 시스템 권한 팝업은 앱의 `CFBundleLocalizations` 를 따른다. fr/ja 를 추가하지 않으면
  프랑스어 기기에서도 **권한 팝업이 한국어**로 뜬다 → 네이티브 재빌드 필요(OTA 불가).

# R7. iOS 지역 확장 선행 조건 (2026-07-30 오너 결정 · 위반 금지)

**1.0.4 가 승인되기 전에는 iOS 판매 지역을 한국 밖으로 넓히지 않는다.**

이유: 권한 팝업 문구(알림·카메라·사진·마이크)는 앱 번들의 `*.lproj` 를 따르는데,
현재 빌드에는 `en.lproj` 에 앱 이름 한 줄만 들어 있다. 그래서

- 영어 기기 → 카메라/사진/마이크 권한 **설명문이 한국어**
- 프랑스·일본 기기 → 위 3개 + **알림 권한 팝업 전체가 한국어**

이건 JS 가 아니라 네이티브라 **OTA 로 못 고친다**. `locales/{en,fr,ja}.json` 에는
정답이 이미 들어 있으므로, `expo prebuild` 로 `*.lproj` 를 다시 생성한 빌드
(1.0.4)를 올리면 해결된다.

현재 상태(2026-07-30): 판매 국가 = 한국뿐, 1.0.3 은 WAITING_FOR_REVIEW.
따라서 해외 사용자는 아직 이 문제를 겪지 않는다 — **지역 확장 순서만 지키면 된다.**

## 1.0.4 배포 순서
1. 1.0.3 승인 대기(대기 순번 유지 — 취소하지 않는다)
2. `expo prebuild --clean` → `en/fr/ja.lproj` 생성 확인
3. 1.0.4 빌드 · 제출
4. **승인 후에** 프랑스·일본 판매 지역 추가

# V7. 검수 케이스 레지스트리 (2026-07-30 신설)

## 왜

내가 손으로 "화면 32개" 목록을 만들고 그게 전부인 줄 알았다. 실제로는 라우트 50개,
확인·경고 팝업 262곳, 알림 진입 7종, 역할 3종이었다. **손으로 적는 목록은 적은 사람이
아는 만큼만 커진다.** 그래서 케이스를 코드에서 생성한다.

```
node scripts/qa-cases-gen.mjs      # 코드에서 케이스 생성 → qa/cases.json
node scripts/qa-report.mjs fr      # 케이스 단위 실행/미실행 판정
```

## 규칙

- **V7-1** 케이스 목록을 손으로 적지 않는다. 화면은 네비게이터에서, 팝업은
  `dialog.alert/confirm` 호출 지점에서, 알림은 알림 type 에서 뽑는다.
  새 화면·새 팝업을 추가하면 다음 실행에서 케이스가 저절로 늘고, 늘어난 만큼 미실행이 된다.
- **V7-2** 순회기(`qaWalk.ts`)는 자기 목록을 갖지 않고 `qa/cases.json` 을 따른다.
- **V7-3** 제외는 생성기의 `EXCLUDED_ROUTES` 에서만 가능하고 사유·승인일이 필수다 → diff 에 보인다.
- **V7-4** 필수 params 가 있는 화면은 `PARAM_FIXTURES` 에 값이 없으면 `fixture-missing`
  으로 남는다. **조용히 빠지지 않는다.**
- **V7-5** 보고는 "몇 화면 봤다" 가 아니라 **"케이스 N/M 실행"** 으로 한다.

## 함정 (다시 밟지 말 것)

- 전체화면 화면(`Alarm`)을 순회 중간에 넣으면 빠져나오지 못해 **이후 케이스가 전부 죽는다**
  → `BLOCKING` 으로 분리.
- 필수 params 없이 화면을 열면 렌더 에러로 NavigationContainer 가 통째로 죽어
  **그 뒤 30개가 실행되지 않는다**. 그런데 표식은 계속 찍히므로 겉보기엔 성공처럼 보인다
  → 그래서 표식에 **도착한 실제 라우트**를 함께 남긴다.
