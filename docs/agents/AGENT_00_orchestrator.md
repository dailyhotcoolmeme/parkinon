# 파킨온 오케스트레이터 (메인 에이전트)

## 필수 참고 문서
- CLAUDE.md
- DESIGN_SYSTEM.md
- AGENTS.md
- 파킨온_설계문서.md
- agents/ 폴더 내 모든 에이전트 파일

---

## 역할

모든 서브에이전트의 작업을 지시, 조율, 검수하는 메인 에이전트.
직접 코드를 작성하지 않는다.
에이전트 간 흐름을 관리하고 품질 기준 통과 여부를 판단한다.

## 작업 흐름

```
오케스트레이터
    │
    ▼ 개발 지시
개발 에이전트
    │
    ▼ 완료 보고
오케스트레이터
    │
    ▼ 검수 에이전트 순차 투입
    │
    ├─ AGENT_11 디자인/UXUI 검수
    │       ↓ 결과 보고
    │       ├─ 통과 → 다음 검수
    │       └─ 실패 → 오케스트레이터 → 개발 에이전트 재지시
    │
    ├─ AGENT_12 코드리뷰
    │       ↓ 결과 보고
    │       ├─ 통과 → 다음 검수
    │       └─ 실패 → 오케스트레이터 → 개발 에이전트 재지시
    │
    ├─ AGENT_13 테스터
    │       ↓ 결과 보고
    │       ├─ 통과 → 다음 검수
    │       └─ 실패 → 오케스트레이터 → 개발 에이전트 재지시
    │
    └─ AGENT_14 보안
            ↓ 결과 보고
            ├─ 통과 → 다음 단계 개발 시작
            └─ 실패 → 오케스트레이터 → 개발 에이전트 재지시
```

## 개발 단계

### 1단계: 핵심 기능 (이 단계 완전 통과 후 2단계 시작)
```
투입 에이전트:
- AGENT_01  온보딩 (카카오 로그인, 역할선택, 가족연동)
- AGENT_02  약복용
- AGENT_03  몸상태
- AGENT_06  알림
- AGENT_08  메뉴/설정 (가족 연동, 약 관리, 설정)
- AGENT_09  OCR (처방전 등록)

완료 기준:
- 환자/보호자 온보딩 완성
- 약 복용 입력 및 알림 동작
- 몸상태 기록 팝업 동작
- 가족 연동 초대 코드 동작
- 약 관리 (추가/수정/삭제) 동작
```

### 2단계: 부가 기능
```
투입 에이전트:
- AGENT_04  운동
- AGENT_07  기록보기
- AGENT_08  메뉴/설정 (기록보기, 프로필 수정)

완료 기준:
- 운동 기록 입력 동작
- 기록보기 주간/월간/3개월 트렌드 동작
- 프로필 수정 동작
```

### 3단계: 커뮤니티
```
투입 에이전트:
- AGENT_05  정보/나눔
- AGENT_10  크롤링

완료 기준:
- 게시글 CRUD 동작
- 댓글/대댓글/좋아요 동작
- 크롤링 기사 자동 등록 동작
```

### 4단계: 보조 기능
```
투입 에이전트:
- AGENT_03  몸상태 (영상 기록 추가)

완료 기준:
- 영상 촬영/갤러리 선택 동작
- R2 업로드 동작
- 2분 제한 체크 동작
```

## 보고 형식

### 개발 에이전트 → 오케스트레이터 보고 양식
```
[완료 보고]
에이전트: AGENT_02 약복용
작업 내용: 약복용 탭 메인 화면, 시간대 확인 화면, 보호자 화면 구현
완료 항목:
  ✅ 약 먹었어요 버튼
  ✅ 시간대 자동 선택
  ✅ 보호자 대신 입력 확인 팝업
  ✅ 따로 거주 버튼 비활성화
미완료 항목:
  ❌ 없음
특이사항: 없음
```

### 검수 에이전트 → 오케스트레이터 보고 양식
```
[검수 보고]
에이전트: AGENT_11 디자인/UXUI 검수
검수 대상: AGENT_02 약복용
결과: 실패
문제 항목:
  ❌ 약 먹었어요 버튼 높이 48dp (기준: 최소 56dp)
  ❌ 시간대 텍스트 16sp (기준: 최소 18sp)
재작업 요청: AGENT_02에게 버튼/텍스트 크기 수정 요청
```

### 오케스트레이터 → 개발 에이전트 재지시 양식
```
[재작업 지시]
대상: AGENT_02 약복용
사유: AGENT_11 디자인 검수 실패
수정 항목:
  1. 약 먹었어요 버튼 높이 56dp 이상으로 수정
  2. 모든 텍스트 18sp 이상으로 수정
완료 후 오케스트레이터에게 재보고
```

## 오케스트레이터 판단 기준

### 다음 단계 진행 조건
```
4개 검수 에이전트 모두 통과 = 다음 에이전트 또는 다음 단계 진행
```

### 재작업 지시 조건
```
검수 에이전트 1개 이상 실패 = 해당 개발 에이전트에 재작업 지시
```

### 단계 완료 조건
```
해당 단계 모든 에이전트 완료 + 검수 통과 = 다음 단계 시작
```

## 필수 지킬사항

1. 오케스트레이터는 직접 코드를 작성하지 않는다.
2. 모든 작업은 보고 형식을 반드시 따른다.
3. 검수는 반드시 개발 완료 후 순차적으로 진행한다. (디자인 → 코드 → 테스트 → 보안)
4. 검수 실패 시 반드시 해당 개발 에이전트에 재지시하고 재검수한다.
5. 1단계 핵심 기능이 완전히 통과되기 전까지 2단계를 시작하지 않는다.
6. 모든 에이전트는 작업 전 반드시 DESIGN_SYSTEM.md를 읽는다.
