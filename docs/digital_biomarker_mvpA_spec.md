## 1. 배경 · 목표

### 1.1 배경 (리서치 doc 요약)
- 파킨슨 임상에서 능동 자가측정 modality는 **finger tapping**(CAPSIT-PD 디지털화)·**reaction time**·**sustained vowel /아/**·**spiral drawing**·**gait/TUG** 등이 1차 출처(Espay 2019, Roche PASADENA, WATCH-PD, mPower, Parkinson@Home)에서 권고·검증되어 있다.
- 핵심 권고는 두 가지로 수렴한다.
  1. **개인 baseline 대비 변화로만 제시**(인구집단 평균 비교 금지) — Espay 2019, MDS Task Force.
  2. **부담↔효용 균형**: 자유등록 mPower는 6개월 87% 이탈, 감독·동기부여형 Roche v2는 일 5.3분으로 96.29% 순응. 약효추적이라는 강한 동기 + 짧은 task가 결합되면 노인 코호트 retention에 유리(추정).
- 한국 시장 현황(리서치 doc F): 국내에 "디지털 객관 측정 + 약효추적 + 보호자 연동 + 한국어"를 통합한 PD 앱은 공백.

### 1.2 차별점 (파킨온 MVP-A 한정)
1. **약효추적 알림 동선 내부에 객관 측정 삽입** — 별도 알림 신설 없이 기존 30분/2시간 알림 본문에 "30초만 해볼까요?" 권유.
2. **보호자 연동** — 한국 가족 케어 문화에 맞춰 측정 결과의 보호자 가시화. 보호자 알림 정책은 기존 약/몸상태 패턴과 동일(토글 ON 기본).
3. **한국어 60대+ UX** — 18sp+/56dp+/아이콘+텍스트/스와이프 최소화/안심·돌봄 톤.

### 1.3 MVP-A 범위
- **포함**: 손가락 두드리기 10초(양손 교대), 반응속도 7회. 환자 결과(실제 측정 수치 + 본인 30일 평균 비교 + 추세 그래프), 환자/보호자 추세 화면, 약효추적 알림 본문에 권유 한 줄 추가, 동의 화면, 본인 30일 baseline·14일 학습 기간, 메뉴 자율 측정(약효추적 측정과 동일 평균 풀에 포함).
- **제외 (MVP-B 이후)**: 음성 /아/, 나선/필기, gait/TUG, 카메라(표정), passive 키스트로크, wearable 연동.

## 2. 확정 결정사항 (변경 금지 — 오너 확정)

> 본 5건은 오너가 사전 확정한 내용이며 본 문서·이후 구현·검수의 단일 기준이다.

### 2.1 측정 modality — 분리 측정 (결합형 금지)
- 임상 표준(CAPSIT-PD, MDS-UPDRS 3.4, WATCH-PD, Roche v2)이 task별 독립 시행이고 결합형의 검증 문헌이 부재하다.
- 두 가지를 한 게임에 합치면 신호 오염(반응속도가 탭핑 리듬에 영향 등) 위험.
- **확정 구성**:
  - **손가락 두드리기 10초** — 양손 검지 교대(주손→비주손→주손…), 화면에 좌/우 동그라미 두 개. CAPSIT-PD 디지털화.
  - **반응속도 7회** — 자극 간격 2~4초 랜덤(예측 방지), 동그라미가 회색→초록으로 색 변할 때 즉시 탭, 색 변화 전 탭은 false start로 기록(점수 미반영, 안내만).

### 2.2 결과 화면 톤 — 실제 측정 수치 + 그래프 + 본인 30일 평균 맥락 (오너 확정 2026-05-25)
- **별 1~3개 매핑 폐기**(오너: "게임이라면서 점수 안 보이는 게 모순"). 결과 화면에 **실제 측정 수치**(예: "오늘 47회! 평소 평균 50회")와 **그래프**(최근 추세 막대)를 노출한다.
- **환자에게도 절대값 노출 허용**(오너 확정 2026-05-25) — 단 "본인 30일 평균" 맥락 텍스트를 항상 함께 제공(인구집단 평균 비교는 여전히 금지).
- **여전히 금지**: 등급·랭킹·캐릭터·의학 판정 표현("OFF", "이상", "악화", "약효 떨어짐"). "변동 큼"·"변동 컸음" 같은 묘사 표현은 사용 OK(의학 판정 아님).
- 환자 화면은 **본인 데이터** 한 차원만(본인의 오늘 수치 + 본인 30일 평균 + 본인 추세 그래프). 인구집단 평균 비교는 §6.5와 같이 절대 금지(Espay 2019 권고).

### 2.3 권유 시점 — 기존 약효추적 알림 안에 끼워 넣음 (신규 알림 X)
- 기존 `effect_tracking_queue` → `process-notification-queue`로 발송되는 약효추적 알림(복용 후 30분/2시간) **본문에 한 줄과 딥링크 액션을 추가**.
- 별도 알림(measurement_queue 같은 것) 신설 금지. 서버 푸시 인프라 무수정 원칙(CLAUDE.md) 보존.
- 비강제 — 스킵 가능. 알림 본문은 약효 컨디션 입력이 1차 동선이고 측정은 부가 액션.

### 2.4 시점 구성 — 30분·2시간 두 시점만, pre 없음
- 측정은 약효추적 알림이 트리거된 시점(post 30m, post 2h)에서만 가능.
- pre(복용 직전) 측정 제외 — 알림이 없고, 강제 trigger는 노인 부담 + 약 복용 흐름 방해.
- **복용 1회당 최대 2회** — 한 복용 cycle에서 30분 1회 + 2시간 1회까지. 같은 시점 재시도는 1회로 카운트(마지막 시도 채택).

### 2.5 결과 표시 정책 — 본인 30일 baseline 대비 + 실제 수치 + 그래프 (오너 확정 2026-05-25)
- **첫 14일**: "기록 누적 중이에요" 안내. 절대 수치는 노출(오늘의 탭 수·평균 RT 등) — 단 "본인 30일 평균" 비교는 표본 부족으로 비활성.
- **14일 이후**: 본인 30일 rolling baseline(평균·표준편차) **수치를 직접 노출** + 오늘 수치와의 차이(비교 문구) + 추세 그래프(최근 14~30일 시계열).
- **별 1~3 매핑 폐기**(§2.2). 임계값 0.5σ/1.0σ 매핑은 결과 화면 표시 산식에서 제거. z-score는 서버 내부 계산용으로만 유지(이상치 탐지·그래프 색 강조 등 보조 목적), 화면에 z 숫자 자체는 노출하지 않음(과학 표기 부담).
- 인구집단 평균 비교 절대 금지(Espay 2019 권고). "또래 평균"·"한국인 평균"·"정상 범위" 등 표현 금지(§6.6 블랙리스트).
- 환자 화면에 탭 수·평균 RT(ms)·CV 등 **실제 수치 노출 OK**. 단 항상 "본인 30일 평균은 X" 맥락 텍스트와 함께 제공.
- 보호자 추세 화면도 환자 정책과 동일(절대 수치 + 본인 평균 비교 + 시계열 그래프, 인구집단 평균은 금지).

## 3. 임상 표준 근거 (리서치 doc 인용)

### 3.1 분리 측정 채택 이유
- **CAPSIT-PD / MDS-UPDRS 3.4**: 손가락 두드리기는 단일 task로 표준화. 결합 측정은 표준 검증 없음.
- **Roche PD Mobile App v2 (Lipsmeier 2022, PMC9287320)**: 10개 task **개별 시행**, 중앙값 ICC 0.90. Hand Turning 0.95 등 단일 task별 신뢰도 확인.
- **WATCH-PD (Adams 2023/2024)**: 자택·주손 손가락 탭핑 ICC 0.95, 클리닉·비주손 0.28 — task 분리 + 환경 통제가 신뢰도 결정.
- **Parkinson@Home (Evers 2020, JMIR DOI 10.2196/19068)**: 발목 센서 AUC 0.82, 위치 결합 0.84 — 결합은 **센서 위치** 결합이고 task 결합이 아님. 본 MVP-A는 동일 modality 안에서의 결합형(반응속도+탭핑 한 게임)을 금지하는 근거로 해석.
- **mPower (Bot 2016, PMC4776701)**: 5 modality를 모두 분리해 시행. 탭핑 8,003명·음성 5,826명 등 modality별 독립 데이터.

### 3.2 핵심 1차 출처 (본 MVP-A 근거)
- Espay AJ et al. *Mov Disord* 2019. DOI 10.1002/mds.27671. PMC6520192 — **개인 baseline 대비 변화 권고**.
- Lipsmeier F et al. *Sci Rep* 2022. DOI 10.1038/s41598-022-15874-4 — Roche PD Mobile App v2 검증(test-retest, 일 5분, 순응도 96%).
- Adams JL et al. *npj PD* 2023 DOI 10.1038/s41531-023-00497-x; 12-mo *npj PD* 2024 DOI 10.1038/s41531-024-00721-2 — WATCH-PD 탭핑 ICC 환경 의존성.
- Lee EC et al. *PLOS One* 2016 DOI 10.1371/journal.pone.0158852 — 한국·기계식 비교 탭핑 PD vs 대조 유의차.
- Bot BM et al. *Sci Data* 2016;3:160011. DOI 10.1038/sdata.2016.11 — mPower retention 87% 이탈(자유등록).
- AAN Telehealth *Neurology* 2021 DOI 10.1212/WNL.0000000000012185 — 스마트폰 원격 PD 모니터링 지지.
- 「의료기기-웰니스 판단기준」 mfds.go.kr seq=14685 / 「디지털의료제품법」 lsiSeq=259299 / 「개인정보보호법 시행령」 제18조 lsId=011468 — 비의료기기·비생체정보 경계.

> 추가 학술 검색은 본 문서 작성 단계에서 불필요. 위 출처로 결정 근거는 충분히 확보된 상태이며, 새 출처가 필요할 때만 보강한다.

### 3.3 반응속도 task 표준 근거
- Roche eSDMT(ICC 0.75, 학습효과 존재) — 인지·반응 task의 한계도 명시.
- 본 MVP-A는 단순 simple reaction time(SRT)으로 단순화(자극 색 변화 → 탭). choice RT나 인지 부담 task가 아니므로 학습효과는 상대적으로 작다(추정). 7회·자극 간격 2~4초 랜덤은 mPower / 일반 SRT 프로토콜 관례를 따른다.

## 4. 사용자 흐름 (환자)

### 4.1 알림 → 진입
1. 복용 후 30분(또는 2시간) — 기존 약효추적 알림 발송(서버 푸시).
2. **알림 본문(변경 후)**:
   - 제목(기존 유지): "💊 약 드신 지 30분 됐어요"
   - 본문 1줄(기존 유지): "몸 상태 어떠세요? 기록해주세요."
   - **본문 추가 1줄(신규)**: "🖐️ 30초만 손가락·반응 체크도 해볼까요?"
   - 액션 버튼/딥링크: 기존 "기록하기"는 그대로 두고, 알림 탭 시 약효 입력 화면 진입 — 입력 후 또는 진입 시 **권유 카드**(§4.2)가 자동 뜸. 별도 알림 액션 버튼 추가는 Phase 2 옵션(§13).

### 4.2 권유 카드 (비강제, 스킵 자유)
- 약효 입력 화면 또는 진입 직후 `AppDialog`로 카드 노출:
  > "🖐️ 30초만 손가락이랑 반응 체크해볼까요?\n오늘 기록이 본인 추세에 쌓여요."
  - 작은 별행(법적 보조): "ⓘ 측정은 진단이 아니에요. 일상 변화를 보는 기록이에요."
  - 버튼 2개 동등 무게(§7-X.4 패턴):
    - [네, 해볼게요] → §4.3
    - [다음에 할게요] → 다이얼로그 닫힘, 기록은 그대로 진행
- 같은 시점에서 한 번 스킵하면 그 시점에는 다시 권유 X(중복 부담 방지).
- 별도 메뉴 진입(메뉴 → 손가락·반응 체크하기)도 항상 가능 — 알림 외 자율 측정 허용(오너 확정 2026-05-25). 자율 측정은 `med_phase = 'self_initiated'`로 기록되며, **약효추적 측정(post_30m/post_2h)과 동일한 평균 풀에 포함**한다(분리하지 않음 — 오너 확정 2026-05-25). 운영상 구분을 위해 phase 값은 별도로 남겨두되, baseline 계산은 통합 풀로 진행.

### 4.3 측정 흐름
1. **준비 카드**(3~5초): "한 손씩 검지로 동그라미를 빠르게 번갈아 두드리세요. 준비되면 시작 버튼을 누르세요." + [시작] 56dp+ 버튼.
2. **탭핑 게임 10초**(§9.2):
   - 화면에 좌·우 큰 동그라미 2개. 큰 카운트다운(10→0).
   - 손떨림 안전책: 시작 1초 grace(첫 1초 탭은 카운트만 하고 분석 제외).
   - 끝나면 자동으로 결과 인터스티셜(0.8초 "잘했어요 😊") → 반응속도 안내로 자동 전환.
3. **반응속도 안내 카드**(3~5초): "회색 동그라미가 초록으로 바뀌면 빠르게 한 번 탭하세요. 7번 반복할게요." + [시작].
4. **반응속도 게임**(§9.3):
   - 자극 간격 2~4초 균등 랜덤. 회색→초록 색 변화 즉시 탭.
   - 색 변화 전 탭 = false start(점수 미반영, 화면에 "조금만 기다려보세요" 안내 후 다음 시도).
   - 7회 완료 또는 false start 7회 누적 시 종료.
5. **결과 화면**(§4.4).

### 4.4 결과 화면 (실제 측정 수치 + 본인 평균 비교 + 추세 그래프) — 오너 확정 2026-05-25
- 화면 상단: **오늘 측정 핵심 수치**를 큰 글씨로 표시(60sp Bold, 주황 `#FF9800`).
  - 예: "오늘 탭 47회" / "오늘 반응속도 평균 412ms"
- 그 아래 18sp+ 본인 평균 비교 한 줄(14일 이후 한정):
  - 예: "평소 평균 50회예요" / "평소 평균 425ms예요"
- 본문 중단: **최근 추세 그래프**(가로 막대그래프, 최근 14~30일, 일별 핵심 지표 1종).
  - 색은 단일 톤(주황 계열) — 별 매핑 색 코드 폐기에 따라 단계별 색 분기 없음. 빈 날은 회색.
- 하단 한 줄 카피(60대 톤, 의학 판정 표현 금지):

  - (※ 한 줄 카피의 분기 기준 임계값은 결과 표시 보조용일 뿐, 별 등급 매핑이 아니다. 산식은 §6.4·부록 A 참조.)
- 보조 안내(작은 별행, 14sp #666666): "본인 추세 기준이에요. 진단이 아니에요."
- 보조 버튼 2개:
  - [추세 보기] → §4.5
  - [닫기]
- **금지**: 등급("A/B/C"), "OFF/이상/악화/약효 떨어짐", 인구 평균·또래 평균·"정상 범위" 비교, 의료 권고 문구("병원 가세요" 등). 어제 vs 오늘 단순 수치 비교는 OK(본인 데이터끼리).

### 4.5 추세 화면 (환자) — §6.5에서 상술

## 6. 결과 표시 정책 (학술적 핵심)

### 6.1 학습 기간 — 첫 14일
- 14일 미만에는 "본인 30일 평균" 비교 표시를 비활성("기록 누적 중" 안내). 단 오늘의 절대 수치(탭 수·평균 RT)는 결과/추세 화면에 표시한다(오너 확정 2026-05-25 — 절대값 환자 노출 허용 정책에 따른 정합).
- 14일 컷오프 근거: WATCH-PD·Roche v2가 1~2주 안정화 후 분석을 진행. mPower도 학습효과·이탈 분석에서 첫 1~2주를 제외. 14일이 정확한 검증값은 아니나 (a) 사용자 안내 가능한 명확한 숫자 (b) baseline 산정 최소 표본 확보(2시점 × 14일 = 28회 최대) 측면에서 채택.
- **오너 확정(2026-05-24)**: 14일 유지. mPower/Roche v2의 학습기간 기준과 일치. 임상적 절대값은 아니므로 베타 사용자 데이터로 7~30일 사이 재검토 가능성은 §15-3에 잔존.

### 6.2 본인 30일 rolling baseline
- 30일 동안의 측정 feature를 슬라이딩 윈도우로 평균(μ)·표준편차(σ) 계산.
- baseline은 **시점별로 분리**해서 계산: post_30m baseline / post_2h baseline. 30분과 2시간 약효 상태가 다르므로 한 baseline에 섞으면 z-score 의미 상실.
- **자율 측정(`med_phase='self_initiated'`)은 동일 평균 풀에 포함**(오너 확정 2026-05-25, §4.2). 별도 baseline row를 만들지 않고, post_30m·post_2h baseline 산정 시 self_initiated 측정도 같은 윈도우에서 함께 평균(μ)·표준편차(σ)에 기여한다. 단 화면 시점 필터(§4.5)에서는 phase 값으로 분류해 표시 가능.
  - **리스크 명시**: 약 복용 상태가 다른 측정(예: 복용 직후가 아닌 임의 시점)이 평균에 섞일 수 있다. 베타 단계에서 자율 측정 비율·분포(self_initiated count / total count, phase별 분산 변화)를 모니터링하고, 자율 측정 분산이 약효추적 분산 대비 유의하게 커지면 후속 정책으로 분리(또는 가중치 차등) 검토(§15-13).
- 약 변경(레보도파 추가/제거·용량 변경)이 감지되면 **비강제 제안 다이얼로그**(오너 확정 2026-05-24): "약이 바뀌었어요. 추세 새로 쌓을까요?" [네, 새로 쌓기]/[기존 추세 유지]. **자동 reset 금지** — 약효추적 추천 기능 §13-6 비강제 패턴과 일관. 사용자 선택 시 `baseline_stats` row를 새 window로 초기화.

### 6.3 z-score 산정 (서버 내부 — z 숫자는 사용자 미노출)
- 핵심 feature 예:
  - 탭핑: 총 탭 수(10초), 평균 인터탭 간격(ITI), ITI CV(coefficient of variation = σ/μ), 좌우 비대칭(주손-비주손 절대차).
  - 반응속도: 평균 RT(ms), RT SD, false start 횟수.
- z = (오늘 feature - μ_30일) / σ_30일.
- **절대 수치(탭 수·평균 RT·본인 평균)는 환자에게 노출**(오너 확정 2026-05-25). 단 z-score 숫자 자체는 환자·보호자 화면에 노출하지 않음(과학 표기 부담, 의학 판정 인상 회피).
- z는 결과 화면 한 줄 카피 분기(§4.4)와 그래프 시각 강조(이상치 일자 표시 보조) 등 내부 계산에만 사용. 별 1~3 매핑은 폐기(§2.2·§6.4).

### 6.4 한 줄 카피 분기 (z 합성 → 텍스트 분기, 별 등급 매핑 폐기)
- 별 1~3 매핑은 **폐기**(오너 확정 2026-05-25, §2.2). 결과 화면은 절대 수치 + 본인 평균 + 그래프가 1차 정보이고, 한 줄 카피는 보조 문구.
- 한 줄 카피 분기에만 z 합성 산식을 사용(부록 A 산식 유지, 등급 라벨만 제거):
  - |z_aggregate| ≤ 0.5 → "오늘은 평소만큼 잘 움직이셨어요 😊"
  - |z_aggregate| > 0.5 → "오늘은 평소보다 변동이 컸어요. 푹 쉬시고 내일 또 해보세요."
  - (3단계가 아니라 2단계로 단순화 — 별 폐기에 따라 중간 단계 텍스트 불필요)
- 가중치는 Phase 1에서 단순 평균(탭핑 0.6 + 반응속도 0.4)로 시작 — 검증 데이터 누적 후 보정.
- **방향성 표현 금지**: "좋아짐/나빠짐"이 아닌 "변동 컸어요" 단방향 표현으로 통일(악화 인상 방지, 의료법 진단 회피). "변동 컸음"은 묘사 표현으로 사용 OK.

### 6.5 추세 화면 데이터 표현 (환자/보호자)
- 시계열 30일 막대(단일 톤, 주황 `#FF9800`). 별 색 코드 3단계는 폐기.
- 본인 30일 평균 라인(가로 점선)을 그래프에 가이드로 노출.
- 시점 필터 3개("30분 후"/"2시간 후"/"전체") — 자율 측정은 별도 탭 없이 통합 풀(§4.2·§6.2).
- 텍스트 요약 한 줄: "최근 7일 동안 평소만큼이 5번, 변동 있는 날이 2번 있었어요."
- **표시 OK 항목**(오너 확정 2026-05-25): 일별 탭 수, 일별 평균 RT(ms), 본인 30일 평균값.
- **표시 금지 항목**: z-score 수치, 인구 평균 비교, "또래 평균"·"%ile"·"정상범위"·"임상적 의의" 등 의학 표기.

### 7.4 환자 측정 완료 → 보호자 푸시 (cross-user)

## 8. 데이터 모델 (Supabase)

> 리서치 doc G-3 토대 + 약효추적 인프라 연동 정교화. 모든 신규 테이블은 환자 본인 + 연결된 보호자만 접근 가능한 RLS 필요.

### 8.1 신규 테이블

```sql
-- 측정 시도(시작) 단위
create table measurements (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  type text not null check (type in ('tapping', 'reaction')),
  started_at timestamptz not null default now(),
  completed_at timestamptz,
  med_intake_id uuid references med_logs(id) on delete set null,
  med_phase text not null check (med_phase in ('post_30m', 'post_2h', 'self_initiated', 'other')),
  trigger_source text not null check (trigger_source in ('notification', 'manual')),
  effect_tracking_queue_id uuid references effect_tracking_queue(id) on delete set null,
  context jsonb,
  deleted_at timestamptz
);

create index idx_measurements_user_started on measurements(user_id, started_at desc);
create index idx_measurements_phase on measurements(user_id, med_phase, started_at desc);

-- 측정 결과 feature (탭핑/반응속도 통합)
create table measurement_features (
  id uuid primary key default gen_random_uuid(),
  measurement_id uuid not null references measurements(id) on delete cascade,
  feature_key text not null,            -- 'tap_count', 'iti_mean_ms', 'iti_cv', 'asymmetry', 'rt_mean_ms', 'rt_sd_ms', 'false_starts'
  value_numeric numeric,
  value_jsonb jsonb,                    -- raw 시리즈(좌/우 탭 timestamps, RT 7개) 보관용
  created_at timestamptz not null default now(),
  unique (measurement_id, feature_key)
);

create index idx_measurement_features_key on measurement_features(measurement_id, feature_key);

-- 본인 baseline (30일 rolling, 시점·feature별 분리)
-- 주의: self_initiated 측정은 post_30m / post_2h baseline 풀에 함께 집계되므로
-- 별도 self_initiated row를 만들지 않는다(§6.2, 오너 확정 2026-05-25).
create table baseline_stats (
  user_id uuid not null references users(id) on delete cascade,
  med_phase text not null check (med_phase in ('post_30m', 'post_2h', 'self_initiated', 'other')),
  feature_key text not null,
  mean numeric not null,
  sd numeric not null,
  n integer not null,
  window_start date not null,
  window_end date not null,
  updated_at timestamptz not null default now(),
  primary key (user_id, med_phase, feature_key)
);

-- 사용자별 동의 기록 (의료기기 회피 디스클레이머 동의 시각)
create table measurement_consents (
  user_id uuid primary key references users(id) on delete cascade,
  consented_at timestamptz not null default now(),
  consent_version text not null,
  withdrew_at timestamptz
);
```

### 8.2 기존 테이블 영향
- `effect_tracking_queue` — **무변경**(§7.1).
- `users` — `push_token` 이미 존재(보호자 푸시용). 신규 컬럼 없음.
- `medications.item_seq` — 별 기능과 무관(이미 약효추적 추천 기능에서 적용 완료).

### 8.3 RLS 정책
- `measurements` / `measurement_features` / `baseline_stats`:
  - 환자 본인: SELECT/INSERT/UPDATE 자기 row.
  - 보호자: SELECT only — `patient_group_members`에 연결된 환자 row만.
  - 삭제는 soft delete(`deleted_at`)로만.
- `measurement_consents`: 본인만 SELECT/INSERT. 보호자 접근 X.

### 8.4 baseline 갱신 정책
- 측정 INSERT 시 트리거 또는 cron(일 1회 새벽)으로 `baseline_stats` 재계산.
- 윈도우: 시점별 최근 30일 모든 측정 feature.
- 표본 부족(< 14일치, < 6회) 시 baseline row를 만들지 않거나 `n` 값으로 분기 → 환자 화면 "기록 누적 중" 안내.

### 8.5 raw 데이터 보존 정책
- `measurement_features.value_jsonb`에 raw 탭 timestamps / RT 7회 배열을 보관(검증·디버깅용).
- 음성·영상 없으므로 PIPA 생체정보(시행령 18조) 별도 동의 불필요. 단 측정 데이터 자체에 대한 동의는 §11에서 별도 받음.
- 보존 기간: raw 6개월 후 자동 삭제(영상 정책과 통일). feature·baseline은 영구 보존.

## 11. 법적 · 동의 처리

### 11.1 비의료기기 디스클레이머 (리서치 doc D-1·9-A 기반)
- 노출 위치: 첫 사용 동의 화면(§9.6) + 결과 화면 보조 안내 + 추세 화면 하단 보조 안내.
- 권장 문안(고정 카피):
  > "본 측정 기능은 의료기기가 아닙니다. 측정 결과는 일상 변화 기록을 돕기 위한 참고 정보이며, 파킨슨병의 진단·치료·예방·예후 판정을 목적으로 하지 않습니다. 증상 변화에 대한 의학적 판단과 약물 조정은 반드시 담당 의료진과 상담하시기 바랍니다."
- 식약처 「의료기기-웰니스 판단기준」(seq=14685) 기준 — 진단·치료·예측·모니터링 아닌 "기록·라이프스타일·건강유지" 범주로 포지셔닝. 「디지털의료제품법」(lsiSeq=259299) SaMD 트랙 진입 회피.

### 11.2 PIPA 별도 동의 필요 여부
- 본 MVP-A는 **음성·영상·얼굴·보행 미포함** → 시행령 제18조 생체인식 특징정보 비해당.
- 탭/반응 timestamp는 생체인식 정보가 아님(키스트로크 다이내믹스 수준의 패턴은 회색지대이나 본 MVP는 단일 task의 raw timestamp + feature만 저장, 신원 식별 목적 아님).
- 결론: PIPA 민감정보 별도 동의는 **법적 필수 아님**. 단 측정 데이터 자체에 대한 동의는 의료 안전·신뢰 차원에서 §9.6 첫 사용 화면으로 받음.

### 11.3 데이터 보존 · 삭제 정책
- `measurement_features.value_jsonb`(raw timestamps) — 6개월 후 자동 삭제(영상 정책과 통일, supabase cron).
- `measurement_features.value_numeric`·`baseline_stats` — 영구 보존.
- `measurements` row — soft delete(`deleted_at`).
- 회원탈퇴 시 — 기존 회원탈퇴 흐름(`delete-account` Edge Function)에 신규 테이블 cascade 추가.

### 11.4 동의 버전 관리
- `measurement_consents.consent_version` — 본 MVP-A는 `"v1-2026-05-24"`. 디스클레이머 본문이 바뀌면 버전 증가 → 다음 진입 시 재동의.

## 13. 구현 단계 (Phase)

> 본 프로젝트는 오케스트레이터 위임 원칙(CLAUDE.md). 실제 구현은 AGENT_01(온보딩·동의)·AGENT_02(약복용 알림 진입)·AGENT_06(알림·서버 푸시)·AGENT_07(기록 보기)·AGENT_08(메뉴) 분배 + AGENT_11~14 검수.

### Phase 0 — 준비·기술 검증 (착수 전 통과 필수)
- **A. 알림 액션 버튼(`[바로 측정하기]`) OTA 가능성 검증 (오너 확정 신설 작업)**:
  - `expo-notifications`의 `setNotificationCategoryAsync`로 categoryIdentifier·actions·deep-link 등록 — **iOS·Android 양쪽 + 한국 시간대(KST)** 실기기 시나리오로 JS만으로 동작하는지 검증.
  - 검증 시나리오: (1) 백그라운드 상태에서 알림 수신 → 액션 버튼 노출 (2) 액션 탭 → 측정 화면 직접 진입 (3) `med_phase` 식별 정확도 (4) Foreground에서도 정상 동작.
  - 통과 시 → JS로만 구현, OTA 배포.
  - 실패 시(특히 iOS category 등록이 네이티브에 닿는 경우) → **한 번 재빌드(prebuild + EAS build) + 새 APK/IPA 출시 → 그 이후 모든 후속 업데이트는 OTA**.
  - 두 트랙 모두 출시 일정 안에 불가 → fallback: 본문 카피만으로 일단 출시 + 다음 정규 빌드에 액션 버튼 추가(§15-fallback).
- **B. `expo-screen-orientation` 의존성 확인**(§16) — 미포함 시 (a) JS 회전 잠금 없이 측정 화면 세로 가정 진행 or (b) 의존성 추가 + APK 재빌드 트랙으로 분리.

## 부록 A. 한 줄 카피 분기 산식 (요약, §6.4 — 별 1~3 매핑 폐기, 오너 확정 2026-05-25)

```
for each feature_key f in WEIGHT_MAP:
  z_f = (today_value[f] - baseline.mean[f]) / baseline.sd[f]
  contrib_f = w_f * |z_f|         # 방향성 제거(악화 인상 방지)

|z_aggregate| = sum(contrib_f)

if |z_aggregate| <= 0.5:  copy = "오늘은 평소만큼 잘 움직이셨어요 😊"
else:                      copy = "오늘은 평소보다 변동이 컸어요. 푹 쉬시고 내일 또 해보세요."
```

가중치(Phase 1 초기값):
- tapping.iti_cv: 0.30
- tapping.tap_count: 0.20
- tapping.asymmetry: 0.10
- reaction.rt_mean_ms: 0.25
- reaction.rt_sd_ms: 0.15

> 별 1~3 등급 매핑은 폐기(§2.2). z_aggregate는 한 줄 카피 분기와 그래프 시각 강조(이상치 일자 표시 보조) 등 내부 계산에만 사용. z 숫자는 화면에 노출하지 않음. 결과 화면 1차 정보는 본인 절대 수치 + 본인 30일 평균 + 추세 그래프.
> 베타 데이터(N=10~30) 수집 후 가중치·임계값 재보정. 본 산식은 의학적 검증값이 아니며 z 수치 자체는 환자 화면에 노출하지 않음.
